[[ability-to-convert-node-based-licenses-to-capacity-based-licensing-in-private-mode]]
=== Possibilité de convertir les licences basées sur les nœuds en licences basées sur la capacité en mode privé

NetApp est heureux d’annoncer la licence basée sur la capacité pour les déploiements Cloud Volumes ONTAP en mode privé. Vous pouvez désormais optimiser les coûts de vos déploiements Cloud Volumes ONTAP en mode privé en convertissant votre licence par nœud en une licence basée sur la capacité. Pour vos déploiements en mode privé, vous pouvez acheter un pack Essentials (bring your own license (BYOL)) directement auprès de NetApp avec une capacité similaire à celle de votre licence par nœud actuelle.

Cette option de conversion prend en charge le plan progressif de NetApp visant à abandonner les licences par nœud au profit des licences basées sur la capacité. Contrairement aux licences par nœud, qui allouent une capacité fixe à chaque système, les licences basées sur la capacité puisent dans un pool de capacité partagé entre vos systèmes Cloud Volumes ONTAP, vous offrant ainsi une plus grande flexibilité pour redistribuer les charges de travail à mesure que vos besoins de stockage évoluent.

[[introducing-simplified-onboarding-of-cloud-volumes-ontap-from-aws-marketplace]]
=== Présentation de l'intégration simplifiée de Cloud Volumes ONTAP depuis AWS Marketplace

NetApp introduit un flux d'intégration simplifié pour Cloud Volumes ONTAP depuis AWS Marketplace, réduisant les étapes manuelles et les frictions liées à l'intégration.

Auparavant, le déploiement Cloud Volumes ONTAP depuis AWS Marketplace nécessitait de naviguer entre plusieurs écrans et de configurer manuellement les rôles, les politiques et les informations d'identification. Cela rendait la prise en main lente et sujette aux erreurs.

Le nouveau processus d'intégration simplifie votre transition d'un abonnement à la place de marché vers un environnement Cloud Volumes ONTAP entièrement opérationnel grâce aux fonctionnalités suivantes :

. Abonnement à la fiche dédiée Cloud Volumes ONTAP sur AWS Marketplace : vous vous abonnez à la fiche autonome Cloud Volumes ONTAP sur AWS Marketplace, achetez un abonnement et configurez votre compte AWS (si vous n’en avez pas déjà un).
. Parcours guidé sur la NetApp Console : Vous configurez votre compte dans la NetApp Console, et la Console vous accompagne automatiquement tout au long du processus de déploiement en affichant le parcours guidé sur le côté droit. Si vous devez quitter la Console, vous pouvez reprendre le parcours guidé ultérieurement.
. Association de votre abonnement : Vous pouvez associer automatiquement votre abonnement à la Console, évitant ainsi les étapes manuelles de liaison.
. Déploiement de l'agent Console avec configuration des identifiants AWS : vous pouvez créer automatiquement les rôles AWS requis. Le processus déploie une pile CloudFormation dans votre compte AWS avec les rôles et politiques nécessaires pour que vous puissiez les examiner, puis les associe à la NetApp Console, éliminant ainsi la configuration manuelle d'IAM. Vous poursuivez ensuite la configuration de l’agent, du réseau et des paramètres du groupe de sécurité pour commencer le déploiement de l’agent.
. Déployez un nouveau système Cloud Volumes ONTAP sur AWS : vous accédez directement à l’ `Quick create`assistant pour un déploiement Cloud Volumes ONTAP plus rapide et simplifié.

La NetApp Console prend désormais en charge l'analyse de configuration bien architecturée pour les systèmes Cloud Volumes ONTAP exécutés dans Microsoft Azure. * *Fiabilité* : Garantit le bon fonctionnement et la constance des charges de travail, même en cas de perturbations.
* *Sécurité* : Protège les données, les systèmes et les actifs grâce à des évaluations des risques et à leur atténuation.
* *Excellence opérationnelle* : Optimise l'architecture pour maximiser la valeur commerciale.
* *Optimisation des coûts* : Réduit et optimise les coûts pour une plus grande valeur commerciale.

[[support-for-next-generation-google-cloud-vms-in-cloud-volumes-ontap-ha]]
=== Prise en charge des machines virtuelles Google Cloud de nouvelle génération dans Cloud Volumes ONTAP HA

Avec la version 9.19.1, NetApp fait passer les déploiements Cloud Volumes ONTAP à haute disponibilité (HA) des machines virtuelles N2 aux machines virtuelles de nouvelle génération de la série Google Cloud C3 pour une expérience plus rapide et plus évolutive.


NOTE: Cette assistance s'applique uniquement aux déploiements HA à zone de disponibilité unique (AZ).

Vous pouvez désormais tirer parti des machines virtuelles de la série C3 lors du déploiement de Cloud Volumes ONTAP 9.19.1 et versions ultérieures sur Google Cloud. Ces machines offrent des performances améliorées et des limites de capacité plus élevées. Elles utilisent Google Virtual NIC (gVNIC) et des disques Hyperdisk Balanced pour des performances dynamiques sur les charges de travail intensives.

Si votre système Cloud Volumes ONTAP exécute la version 9.19.1 ou ultérieure, les packages préconfigurés que vous utilisez pour des déploiements simplifiés dans une seule zone de disponibilité utilisent automatiquement des machines virtuelles C3, tout en vous permettant de personnaliser les paramètres d'IOPS et de débit en fonction des besoins de votre charge de travail. De même, lors de la création d'agrégats, vous pouvez ajouter des disques Zonal Hyperdisk Balanced pour obtenir de meilleures performances et une meilleure évolutivité sur Google Cloud. Vous pouvez également sélectionner les variantes LSSD des machines de la série C3 pour une prise en charge par défaut du Flash Cache.

Notez ces points :

* Dans vos déploiements Cloud Volumes ONTAP, vous ne pouvez pas changer des machines virtuelles C3 en machines virtuelles de la série N2 et inversement. Cependant, vous pouvez changer de type d'instance parmi les différentes variantes de la famille C3.
+

NOTE: Le changement de type d'instance au sein de la famille C3 peut prendre plus de temps en fonction du nombre de disques de données connectés. Planifiez votre configuration à l'avance pour éviter tout impact sur les performances.

* Lors du changement de type d'instance, si vous sélectionnez c3-standard-44 ou c3-standard-88 et leurs variantes SSD locales (LSSD) comme machine virtuelle cible, le niveau de réseau de sortie du service réseau Google _Tier-1_ est appliqué automatiquement. Si vous revenez à une autre variante C3, le niveau de réseau de sortie est défini sur _Standard_.
+

NOTE: Le passage au niveau _Tier-1_ du réseau de sortie engendre des coûts supplémentaires. Prévoyez le déploiement et la mise à niveau en conséquence.

* Si vous sélectionnez les variantes LSSD de C3, le cache Flash est activé par défaut. Vous ne pouvez pas changer de variante LSSD de C3 dans votre déploiement Cloud Volumes ONTAP, même si la variante cible prend en charge le cache Flash.
* Sur vos machines virtuelles C3, vous pouvez ajouter des volumes aux agrégats nouveaux et existants.
* Lors de la réplication d'un système Cloud Volumes ONTAP avec un type de VM N2 vers un type de VM C3, le type de disque est défini par défaut sur Hyperdisk Balanced.
* Vous pouvez modifier les paramètres IOPS et de débit lors de l’ajout d’agrégats via la NetApp Console ou en utilisant l’ `PUT /gcp/ha/aggregates/{workingEnvironmentId}/{aggregateName}` API.


https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-configs-gcp.html["Configurations prises en charge pour Cloud Volumes ONTAP dans Google Cloud"^]

https://docs.cloud.google.com/compute/docs/general-purpose-machines#c3_series["Google documents : série de machines C3"^]

[[introducing-access-roles-for-cloud-volumes-ontap]]
=== Introduction des rôles d'accès pour Cloud Volumes ONTAP

NetApp introduit des rôles de gestion des identités et des accès (IAM) pour Cloud Volumes ONTAP, permettant le contrôle d'accès basé sur les rôles (RBAC) pour une meilleure sécurité et une conformité facilitée. Les utilisateurs peuvent continuer à se connecter à la NetApp Console en utilisant leurs identifiants existants pour les opérations Cloud Volumes ONTAP. Cependant, l'authentification est désormais acheminée via la fédération d'identités, ce qui permet à l'administrateur de la Console d'exercer un contrôle plus granulaire sur ces fonctions. Chaque utilisateur doit disposer de l'un des rôles suivants pour effectuer toute opération sur Cloud Volumes ONTAP. Sans rôle, les utilisateurs ne peuvent ni consulter ni accéder aux instances Cloud Volumes ONTAP.

* *Cloud Volumes ONTAP viewer* : Accorde un accès en lecture seule aux écrans et onglets de Cloud Volumes ONTAP. Certains écrans et boutons d’action sont désactivés dans ce rôle.
* *Cloud Volumes ONTAP operator* : Permet d’effectuer les tâches de gestion quotidiennes, telles que l’ajout de volumes, la gestion du stockage et la configuration de la réplication.
* *Administrateur Cloud Volumes ONTAP* : Fournit un accès complet à toutes les opérations Cloud Volumes ONTAP.


L'administrateur de la NetApp Console attribue des rôles aux utilisateurs Cloud Volumes ONTAP depuis *Administration > Identité*. Les autorisations de rôle sont basées sur l'organisation de l'utilisateur et s'appliquent à tous les systèmes Cloud Volumes ONTAP de cette organisation.

Cloud Volumes ONTAP applique le RBAC à l'aide d'un cache local des autorisations de chaque utilisateur, qui est actualisé automatiquement une fois par heure. Lorsqu'un utilisateur se voit attribuer un nouveau rôle ou que son rôle existant est modifié, la prise en compte de cette modification peut prendre jusqu'à une heure, après quoi tous les workflows autorisés par les rôles sont activés.


NOTE: Lors du premier déploiement d'un agent Console ou de la mise à niveau d'un agent Console existant vers Console 4.9.0 ou une version ultérieure, un processus d'initialisation unique attribue automatiquement les rôles Cloud Volumes ONTAP à tous les utilisateurs existants de l'organisation. Ce processus peut prendre jusqu'à 30 minutes pour être terminé. Une fois terminé, la Console attribue les rôles appropriés aux utilisateurs existants.

Les rôles Cloud Volumes ONTAP s'appliquent aux environnements Amazon Web Service (AWS), Microsoft Azure (Azure) et Google Cloud.

[[support-for-new-ec2-instances-for-cloud-volumes-ontap-in-aws]]
=== Prise en charge des nouvelles instances EC2 pour Cloud Volumes ONTAP dans AWS

Cloud Volumes ONTAP 9.16.1 et versions ultérieures prennent en charge les familles d'instances EC2 M6id et M6idn pour les déploiements à nœud unique et à haute disponibilité (HA) sur AWS, qu'ils soient nouveaux ou existants. Ces instances de 6e génération offrent une puissance de traitement plus rapide, des capacités réseau renforcées et des performances supérieures aux systèmes à usage général de 5e génération.

* Instances M6id : Elles offrent un équilibre entre puissance de calcul et mémoire grâce à un stockage NVMe local haute vitesse et faible latence. Toutes les tailles d’instances M6id prennent en charge le cache Flash. Ces instances sont parfaitement adaptées aux charges de travail telles que l’enregistrement de données et le traitement multimédia.
* *Instances M6idn* : Offrent les mêmes capacités de stockage NVMe local que les instances M6id. Toutes les tailles d’instances M6idn prennent en charge Flash Cache.


Nous déconseillons les instances de petite taille m6id.xlarge, m6id.2xlarge, m6idn.xlarge et m6idn.2xlarge pour les charges de travail exigeantes en termes de performances ou de mémoire. Pour ces charges de travail, privilégiez une instance dotée d'un nombre de cœurs plus élevé et d'une mémoire plus importante.

Pour plus d'informations, consultez  https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-configs-aws.html["Configurations prises en charge pour Cloud Volumes ONTAP dans AWS"^].

[[flexible-billing-for-cloud-volumes-ontap-and-data-services-in-aws]]
=== Facturation flexible pour Cloud Volumes ONTAP et les services de données dans AWS

NetApp propose des options de facturation améliorées pour vos abonnements Cloud Volumes ONTAP dans AWS, vous offrant un meilleur contrôle sur la façon dont vous payez la capacité Cloud Volumes ONTAP et les services de données NetApp, tels que NetApp Backup and Recovery. Auparavant, toute l’utilisation de Cloud Volumes ONTAP et des services de données était facturée ensemble via l’offre NetApp Intelligent Services (NIS) sur la place de marché AWS.

Suite aux modifications apportées au programme de remises pour entreprises AWS (EDP), NetApp a introduit un abonnement Cloud Volumes ONTAP autonome sur la place de marché AWS qui vous permet de dissocier la facturation de la capacité Cloud Volumes ONTAP de celle des services de données. Cette dissociation vous offre une plus grande flexibilité dans la gestion de vos crédits et coûts EDP. NetApp recommande d'utiliser l'abonnement autonome pour une meilleure gestion des coûts liés à votre utilisation de Cloud Volumes ONTAP, tout en continuant d'utiliser l'abonnement NIS pour la facturation des services de données après le 31 juillet 2026, lorsque les exigences EDP entreront en vigueur.

L'abonnement Cloud Volumes ONTAP autonome sur AWS prend uniquement en charge les packages de licence Essentials ou Freemium valides, basés sur la capacité. Le package Professional n'est pas pris en charge. Vous pouvez choisir le mode de facturation qui correspond le mieux à vos besoins :

* *Abonnement Cloud Volumes ONTAP autonome (recommandé)* : payez votre utilisation de Cloud Volumes ONTAP via l’abonnement autonome sur la place de marché AWS, tout en continuant à facturer les services de données via l’abonnement NIS. C’est l’option recommandée pour la plupart des clients qui disposent à la fois d’un abonnement autonome et d’un abonnement NIS associés à leur compte AWS dans la NetApp Console.
* *Abonnement NIS combiné* : payez à la fois Cloud Volumes ONTAP et les services de données ensemble via l'inscription NIS existante. La formule combinée sera valable pour les clients existants qui ont uniquement des abonnements NIS associés à leur compte AWS dans la NetApp Console. Cependant, NetApp recommande de définir vos préférences de facturation pour votre utilisation de Cloud Volumes ONTAP et de passer à l'abonnement autonome pour une meilleure gestion des coûts.


Selon votre type d'abonnement, vous bénéficiez des scénarios suivants :

.Abonnement autonome uniquement (nouveaux clients)

.Abonnements autonomes et NIS (clients existants)
Si votre compte AWS comprend à la fois un abonnement NIS et un abonnement autonome, et que vous n'avez pas défini de préférence de facturation dans l'onglet *Préférences de facturation* de la NetApp Console, l'utilisation de Cloud Volumes ONTAP continue d'être facturée par défaut via NIS. Ceci est également le comportement par défaut pour toute instance Cloud Volumes ONTAP exécutant le package Professional, car l'offre autonome ne prend pas en charge Professional. Vous pouvez définir une préférence de facturation et choisir le mode de facturation de chaque service :

* Configurez l'abonnement autonome comme compte de facturation préféré pour Cloud Volumes ONTAP (avec le package Essentials). Si vous ne possédez que le package Professional, vous pouvez le convertir en package Essentials et facturer votre utilisation de Cloud Volumes ONTAP en définissant la préférence de facturation. Nous recommandons cette méthode car elle vous permet de gérer vos crédits EDP Cloud Volumes ONTAP plus efficacement.
* Utilisez l'abonnement NIS pour la facturation des services de données ou l'utilisation de Cloud Volumes ONTAP via le pack Professionnel. Lors du déploiement, activez le service de données *Backup and Recovery* et sélectionnez le pack de licences Professionnel pour facturer les services de données via l'abonnement NIS.


.Abonnement NIS uniquement (clients existants)
Ceci s'applique si vous êtes déjà client et disposez d'abonnements NIS associés à votre compte AWS. Vous pouvez continuer à facturer Cloud Volumes ONTAP et les services de données ensemble comme actuellement. Cependant, NetApp recommande de passer à l'approche d'abonnement autonome pour une meilleure gestion des coûts de votre utilisation de Cloud Volumes ONTAP :

* Abonnez-vous à une nouvelle fiche produit autonome sur le portail AWS.
* Associez l'abonnement autonome à votre compte AWS.
* Définissez votre préférence de facturation sur l’abonnement autonome pour l’utilisation de Cloud Volumes ONTAP avec le forfait Essentials.
* (Le cas échéant) Convertissez votre forfait Professional en forfait Essentials et définissez votre préférence de facturation.
* Continuez à facturer les services de données via votre abonnement NIS.

=== Possibilité de gérer les paramètres proxy de l'agent NetApp Console pour Cloud Volumes ONTAP

Vous pouvez désormais gérer les paramètres de proxy sur l’agent NetApp Console pour Cloud Volumes ONTAP, même si vous perdez la connexion ou si le proxy est mal configuré. Auparavant, si l’agent Console ne pouvait pas se connecter à Cloud Volumes ONTAP pendant 20 minutes, il remplaçait vos paramètres de proxy manuels par les paramètres par défaut. Cela provoquait des échecs de communication, y compris des problèmes avec les messages AutoSupport. Pour conserver vos paramètres de proxy pour les systèmes existants, exécutez l’appel d’API suivant :

`PUT /occm/config`

Incluez le paramètre suivant dans le corps de la requête :

[source, json]
----
{
  "proxyMode": "No_Overwrites"
}
----
Le mode par défaut est standard, ce qui signifie que l'agent de la Console remplace vos paramètres de proxy par les valeurs par défaut s'il ne parvient pas à se connecter à Cloud Volumes ONTAP pendant 20 minutes.

=== Prise en charge de Cloud Volumes ONTAP pour les machines virtuelles Google Cloud de nouvelle génération

Avec la version 9.18.1, NetApp fait passer les nouveaux déploiements Cloud Volumes ONTAP des machines virtuelles N2 aux machines virtuelles de la série C3 de nouvelle génération de Google Cloud, pour une expérience plus rapide et plus évolutive. Vous pouvez désormais tirer parti des machines virtuelles de la série C3 lors du déploiement de Cloud Volumes ONTAP 9.18.1 et versions ultérieures sur Google Cloud. Les machines de la série C3 offrent des performances améliorées et des limites de capacité plus élevées grâce à l'utilisation de Google Virtual NIC (gVNIC) et de disques Hyperdisk Balanced, garantissant des performances dynamiques pour les charges de travail intensives.


NOTE: Pour le moment, Cloud Volumes ONTAP prend en charge la série C3 uniquement dans les déploiements à nœud unique.

Si votre système Cloud Volumes ONTAP exécute la version 9.18.1 ou ultérieure, les packages préconfigurés que vous utilisez pour des déploiements sur un seul nœud utilisent automatiquement des machines virtuelles C3, tout en vous permettant de personnaliser les paramètres d'IOPS et de débit en fonction des besoins de votre charge de travail. De même, lors de la création d'agrégats, vous pouvez ajouter des disques Hyperdisk Balanced pour obtenir de meilleures performances et une meilleure évolutivité dans Google Cloud. De plus, vous pouvez sélectionner les variantes LSSD des machines de la série C3 pour une prise en charge par défaut du Flash Cache.

Il est impossible de modifier le type de disque des machines virtuelles C3 lors de l'ajout de volumes aux agrégats, car C3 ne prend en charge que les disques Hyperdisk Balanced. De même, lors de la réplication d'un système avec des machines virtuelles N2 vers une machine virtuelle C3, le type de disque est défini par défaut sur Hyperdisk Balanced.

[[worm-and-arp-functionalities-are-no-longer-chargeable]]
=== Les fonctionnalités WORM et ARP ne sont plus payantes

Les fonctionnalités intégrées de protection des données et de sécurité de WORM (Write Once Read Many) et ARP (Autonomous Ransomware Protection) seront proposées avec les licences Cloud Volumes ONTAP sans frais supplémentaires.  Le nouveau modèle de tarification s'applique aux abonnements BYOL et PAYGO/marketplace nouveaux et existants d'AWS, Azure et Google Cloud.  Les licences basées sur la capacité et sur les nœuds contiendront ARP et WORM pour toutes les configurations, y compris les paires à nœud unique et à haute disponibilité (HA), sans frais supplémentaires.

La tarification simplifiée vous apporte les avantages suivants :

* Les comptes qui incluent actuellement WORM et ARP n'entraîneront plus de frais pour ces fonctionnalités.  À l’avenir, votre facturation ne comportera que des frais d’utilisation de la capacité, comme c’était le cas avant ce changement.  WORM et ARP ne seront plus inclus dans vos futures factures.
* Si vos comptes actuels n'incluent pas ces fonctionnalités, vous pouvez désormais opter pour WORM et ARP sans frais supplémentaires.
* Toutes les offres Cloud Volumes ONTAP pour tous les nouveaux comptes excluront les frais pour WORM et ARP.


En savoir plus sur ces fonctionnalités :

* https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-protecting-ransomware.html["Activer les solutions de protection contre les ransomwares NetApp pour Cloud Volumes ONTAP"]

=== Prise en charge des disques gérés Premium SSD v2 dans Azure

Les disques managés Premium SSD v2 sont désormais pris en charge dans les systèmes Cloud Volumes ONTAP sur Azure. Ces disques Premium offrent des performances supérieures avec une latence réduite à moindre coût, aussi bien pour les nœuds uniques que pour les paires haute disponibilité (HA), par rapport aux disques managés Premium SSD. Comme les autres disques managés, la taille maximale d’un disque est de 32 Tio. Les performances (capacité, débit et IOPS) d’un disque managé Premium SSD v2 peuvent être configurées, ce qui permet d’optimiser les coûts des charges de travail tout en répondant à l’évolution des besoins en performances.



[[deploy-ha-pairs-in-single-availability-zones-in-azure]]
=== Déployez des paires haute disponibilité dans des zones de disponibilité uniques dans Azure

À partir de Cloud Volumes ONTAP 9.15.1, vous pouvez déployer des instances de machines virtuelles (VM) en mode haute disponibilité (HA) dans une seule zone de disponibilité (AZ) dans Azure. Contrairement aux déploiements non zonés précédents, Cloud Volumes ONTAP 9.15.1 utilise Microsoft Virtual Machines Scale Sets en mode d'orchestration flexible pour déployer toutes les ressources, y compris des domaines de panne distincts au sein de la même AZ, garantissant une disponibilité optimale. Ce mode de déploiement utilise par défaut des disques managés SSD v2 Premium lorsque les conditions suivantes sont remplies :

* La version de Cloud Volumes ONTAP est 9.15.1 ou ultérieure.
* La région et la zone sélectionnées prennent en charge les disques SSD Premium v2 gérés. Pour plus d’informations sur les régions prises en charge, consultez  https://azure.microsoft.com/en-us/explore/global-infrastructure/products-by-region/["Site Web Microsoft Azure : produits disponibles par région"^]. Pour savoir comment les ajouter, consultez  https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-deploying-otc-azure.html#launching-a-cloud-volumes-ontap-ha-pair-in-azure["Lancement d'une paire haute disponibilité Cloud Volumes ONTAP dans Azure"^].
* L'abonnement est enregistré pour la fonctionnalité  `Microsoft.Compute/VMOrchestratorZonalMultiFD` Microsoft. https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-saz-feature.html["Découvrez comment activer VMOrchestratorZonalMultiFD pour une seule zone de disponibilité"^].


Si l'un de ces critères n'est pas rempli, le mode de déploiement non zonal précédent pour le stockage localement redondant (LRS) devient effectif.



[[support-for-virtual-machines-scale-sets-to-unify-all-azure-ha-types]]
=== Prise en charge des groupes de machines virtuelles identiques pour unifier tous les types de haute disponibilité Azure

Cloud Volumes ONTAP 9.15.1 exploite les groupes de machines virtuelles identiques en mode d'orchestration flexible sur Azure pour déployer des instances de machines virtuelles (VM) dans des zones de disponibilité uniques pour des paires haute disponibilité (HA). [source, json]

----

Un nouveau package professionnel vous permet de regrouper Cloud Volumes ONTAP et Cloud Backup Service en utilisant un contrat annuel de la place de marché AWS. Le paiement s'effectue par Tio. Cet abonnement ne vous permet pas de sauvegarder les données sur site.

Si vous choisissez cette option de paiement, vous pouvez provisionner jusqu'à 2 PiB par système Cloud Volumes ONTAP via des disques EBS et une hiérarchisation vers le stockage d'objets S3 (nœud unique ou HA).

Aller à la https://aws.amazon.com/marketplace/pp/prodview-q7dg6zwszplri["Page AWS Marketplace"^] pour afficher les détails des prix et accéder à la https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes["Notes de version de Cloud Volumes ONTAP"^] pour en savoir plus sur cette option de licence.



[[tags-on-ebs-volumes-in-aws]]
=== Balises sur les volumes EBS dans AWS

BlueXP ajoute désormais des balises aux volumes EBS lorsqu'il crée un nouvel environnement de travail Cloud Volumes ONTAP .  Les balises ont été créées précédemment après le déploiement de Cloud Volumes ONTAP .

Ce changement peut être utile si votre organisation utilise des politiques de contrôle des services (SCP) pour gérer les autorisations.



[[minimum-cooling-period-for-auto-tiering-policy]]
=== Période de refroidissement minimale pour la politique de hiérarchisation automatique

Si vous avez activé la hiérarchisation des données sur un volume à l’aide de la stratégie de hiérarchisation _auto_, vous pouvez désormais ajuster la période de refroidissement minimale à l’aide de l’API.

https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-tiering.html#changing-the-cooling-period-for-the-auto-tiering-policy["Apprenez à régler la période de refroidissement minimale."]



[[enhancement-to-custom-export-policies]]
=== Amélioration des politiques d'exportation personnalisées

Lorsque vous créez un nouveau volume NFS, BlueXP affiche désormais les stratégies d'exportation personnalisées par ordre croissant, ce qui vous permet de trouver plus facilement la stratégie d'exportation dont vous avez besoin.



[[deletion-of-old-cloud-snapshots]]
=== Suppression des anciens instantanés du cloud

BlueXP supprime désormais les anciens snapshots cloud des disques racine et de démarrage créés lors du déploiement d'un système Cloud Volumes ONTAP et à chaque mise hors tension.  Seuls les deux instantanés les plus récents sont conservés pour les volumes racine et de démarrage.

Cette amélioration permet de réduire les coûts des fournisseurs de cloud en supprimant les instantanés qui ne sont plus nécessaires.

Notez qu’un connecteur nécessite une nouvelle autorisation pour supprimer les instantanés Azure. https://docs.netapp.com/us-en/bluexp-setup-admin/reference-permissions-azure.html["Consultez la dernière politique de connecteur pour Azure"^] .

----
"Microsoft.Compute/snapshots/delete"

[[aws-encryption-with-customer-managed-cmks]]
=== Chiffrement AWS avec CMK gérés par le client

BlueXP vous a toujours permis de crypter les données Cloud Volumes ONTAP à l'aide d'AWS Key Management Service (KMS).  À partir de Cloud Volumes ONTAP 9.9.0, les données sur les disques EBS et les données hiérarchisées sur S3 sont chiffrées si vous sélectionnez une CMK gérée par le client.  Auparavant, seules les données EBS étaient cryptées.

Notez que vous devrez fournir au rôle IAM Cloud Volumes ONTAP un accès pour utiliser la CMK.

https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/task-setting-up-kms.html["En savoir plus sur la configuration d'AWS KMS avec Cloud Volumes ONTAP"] .

=== Réduction de l'adresse IP dans Google Cloud

Nous avons réduit le nombre d'adresses IP requises pour Cloud Volumes ONTAP 9.8 et versions ultérieures dans Google Cloud. Vous avez également la possibilité d'ignorer la création du LIF de gestion SVM lors de l'utilisation de l'API, ce qui réduirait le besoin d'une adresse IP supplémentaire.

https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/reference-networking-gcp.html#requirements-for-cloud-volumes-ontap["En savoir plus sur les exigences en matière d'adresse IP dans Google Cloud"] .

[[aws-outposts]]
=== Avant-postes AWS

Il y a quelques mois, nous avons annoncé que Cloud Volumes ONTAP avait obtenu la désignation Amazon Web Services (AWS) Outposts Ready.  Aujourd'hui, nous sommes heureux d'annoncer que nous avons validé BlueXP et Cloud Volumes ONTAP avec AWS Outposts.

Si vous disposez d'un Outpost AWS, vous pouvez déployer Cloud Volumes ONTAP dans cet Outpost en sélectionnant le VPC Outpost dans l'assistant Environnement de travail. L'expérience est la même que pour tout autre VPC résidant dans AWS. Notez que vous devrez d’abord déployer un connecteur dans votre AWS Outpost.

Il y a quelques limitations à souligner :

* Seuls les systèmes Cloud Volumes ONTAP à nœud unique sont actuellement pris en charge
* Les instances EC2 que vous pouvez utiliser avec Cloud Volumes ONTAP sont limitées à ce qui est disponible dans votre Outpost
* Seuls les SSD à usage général (gp2) sont actuellement pris en charge
