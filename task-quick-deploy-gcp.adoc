= Déployez Cloud Volumes ONTAP avec Quick create
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Vous pouvez déployer Cloud Volumes ONTAP sur Amazon Web Services (AWS), Microsoft Azure et Google Cloud en utilisant  `Quick create` pour un déploiement plus rapide, aussi bien en configuration mono-nœud qu'en haute disponibilité (HA). Ce processus simplifié réduit le nombre d'étapes de déploiement par rapport à la méthode avancée en définissant automatiquement les valeurs par défaut sur une seule page et en minimisant la navigation.

.Avant de commencer
Avant de commencer, assurez-vous d'avoir les éléments suivants :

.Étapes
. Dans le menu de navigation de gauche, sélectionnez *Stockage > Gestion*.
. [[subscribe]]Sur la page Canvas, cliquez sur *Ajouter un système* et suivez les instructions.
. Sélectionnez votre fournisseur de cloud (*Amazon Web Services*, *Microsoft Azure* ou *Google Cloud*) > *Cloud Volumes ONTAP/Cloud Volumes ONTAP HA* > *Ajouter nouveau*. L’option *Création rapide* est sélectionnée par défaut.

.Détails du système
. *Compte/fournisseur de cloud/identifiants/projet Google Cloud* : Les informations relatives au compte et à l’abonnement sont automatiquement renseignées à partir de votre agent Console. Si vous possédez plusieurs comptes ou abonnements, sélectionnez celui que vous souhaitez utiliser. Si aucun agent Console n’est disponible, vous serez invité à  https://docs.netapp.com/us-en/console-setup-admin/concept-agent-install-options.html["créer un agent de console"^].
. *Nom* : Saisissez un nom pour votre système Cloud Volumes ONTAP (également appelé nom du cluster). La NetApp Console utilise le nom du système (cluster) pour nommer le système Cloud Volumes ONTAP et l’instance de machine virtuelle. Il utilise également ce nom comme préfixe pour le groupe de sécurité prédéfini, si vous sélectionnez cette option.
. *Identifiants ONTAP* : Il s’agit des identifiants du compte administrateur du cluster Cloud Volumes ONTAP. Vous pouvez utiliser ces identifiants pour vous connecter à Cloud Volumes ONTAP via ONTAP System Manager ou l’interface de ligne de commande ONTAP. Vous pouvez conserver le nom d’utilisateur par défaut _admin_ ou le remplacer par un nom d’utilisateur personnalisé.
. *Étiquettes* : Les étiquettes sont les métadonnées de vos ressources AWS ou Azure. La Console ajoute les étiquettes à l’instance Cloud Volumes ONTAP et à chaque ressource associée à l’instance. Vous pouvez ajouter jusqu’à 15 étiquettes depuis l’interface utilisateur lors de la création d’un système Cloud Volumes ONTAP, puis en ajouter d’autres après sa création. Pour plus d’informations, consultez :

.Déploiement et configuration
. *Type de déploiement/topologie* : Sélectionnez le type de déploiement que vous souhaitez utiliser, nœud unique, haute disponibilité (HA) dans une seule zone de disponibilité (AZ) ou HA dans plusieurs AZ.
. *Configuration réseau* : Saisissez les informations réseau que vous avez enregistrées dans la feuille de planification pour les régions, les VNets et les sous-réseaux.
+
.. *Région* : Par défaut, la région du compte cloud associé aux ressources est sélectionnée.
.. *Zone de disponibilité* : Vous pouvez sélectionner la zone de disponibilité en fonction du type de déploiement que vous choisissez, et si la région sélectionnée prend en charge la zone de disponibilité.
.. *Sous-réseau* : Sélectionnez un sous-réseau pour la région.
+
[role="tabbed-block"]
====
.Pour AWS
--
*VPC* : Pour AWS, saisissez un réseau Amazon Virtual Private Cloud (VPC) pour la région avec un sous-réseau conforme à votre déploiement prévu.

.Haute disponibilité AWS
Si vous avez sélectionné une configuration HA, saisissez les informations suivantes :

.HA dans une seule AZ
... *Accès médiateur* : spécifiez les informations d'accès au médiateur.  Le médiateur est une instance distincte qui surveille l’état de santé de la paire HA et fournit le quorum en cas de panne.  Fournissez le nom de la paire de clés pour permettre à l'instance de médiateur de se connecter au service AWS EC2 et sélectionnez la méthode de connexion.


.HA dans plusieurs AZ
... *Zones de disponibilité et médiateur* : sélectionnez les zones de disponibilité (AZ) pour chaque nœud et le médiateur ainsi que les sous-réseaux correspondants où vous souhaitez déployer la paire Cloud Volumes ONTAP HA.
... *IP flottantes* : si vous avez choisi plusieurs AZ, spécifiez les adresses IP flottantes pour les services NFS et CIFS et la gestion du cluster et de la SVM.  Les adresses IP doivent être en dehors du bloc CIDR pour tous les VPC de la région.  Pour plus de détails, reportez-vous àlink:https://docs.netapp.com/us-en/bluexp-cloud-volumes-ontap/reference-networking-aws.html#requirements-for-ha-pairs-in-multiple-azs["Exigences réseau AWS pour Cloud Volumes ONTAP HA dans plusieurs zones de disponibilité"^] .
... *Accès médiateur* : spécifiez les informations d'accès au médiateur.  Le médiateur est une instance distincte qui surveille l’état de santé de la paire HA et fournit le quorum en cas de panne.  Fournissez le nom de la paire de clés pour permettre à l'instance de médiateur de se connecter au service AWS EC2 et sélectionnez la méthode de connexion.
... *Tables de routage* : si vous avez choisi plusieurs AZ, sélectionnez les tables de routage qui incluent les routes vers les adresses IP flottantes.  Si vous disposez de plusieurs tables de routage, il est important de sélectionner les tables de routage correctes.  Dans le cas contraire, certains clients risquent de ne pas avoir accès à la paire Cloud Volumes ONTAP HA.  Pour plus d'informations sur les tables de routage, reportez-vous à la http://docs.aws.amazon.com/AmazonVPC/latest/UserGuide/VPC_Route_Tables.html["Documentation AWS : Tables de routage"^] .


.Recharge et services
*Abonnement Marketplace* : Dans AWS, sélectionnez l’abonnement AWS Marketplace que vous souhaitez utiliser avec ce système Cloud Volumes ONTAP.

--
.Pour Azure
--
*VNET* : Sélectionnez le réseau virtuel Azure (VNet) requis. Pour plus d’informations sur les exigences relatives au VNet, consultez link:reference-networking-azure.html#networking-for-azure-vnet-encryption["Mise en réseau pour le chiffrement Azure VNet"].

--
.Pour Google Cloud
--
*VPC et sous-réseau* : Pour Google Cloud, saisissez un réseau Google Virtual Private Cloud (VPC) pour la région et un sous-réseau conformément à votre déploiement prévu.

.HA dans une seule AZ ou dans plusieurs AZ
Si vous avez sélectionné une configuration HA, saisissez les informations suivantes : *Zone pour les nœuds 1 et 2, et le médiateur* : Ajoutez les zones des deux nœuds et du médiateur. *Connectivité* : Sélectionnez quatre VPC différents pour la configuration HA et un sous-réseau dans chaque VPC. Pour plus d’informations sur VPC-1, VPC-2 et VPC-3, consultez link:reference-networking-gcp.html#requirements-specific-to-single-node-systems["Règles pour VPC-1, VPC-2 et VPC-3"].


NOTE: Cloud Volumes ONTAP 9.19.1 et versions ultérieures prennent en charge link:concept-ha-google-cloud.html["disques partagés pour les configurations HA à zone de disponibilité unique"], rendant l'instance de médiateur optionnelle ou redondante. Dans cette configuration, vous n'avez pas besoin d'une zone de médiateur, d'un VPC ni d'un sous-réseau pour la réplication des données.

.Recharge et services
. *Licence* : Sélectionnez le type de licence que vous souhaitez utiliser avec ce système Cloud Volumes ONTAP. Vous pouvez choisir entre les licences Professional, Essentials et Freemium. Pour plus d’informations sur les différentes licences, consultez link:concept-licensing.html["En savoir plus sur les licences Cloud Volumes ONTAP"^].
. *Services et fonctionnalités de données* : Gardez les services activés ou désactivez les services que vous ne souhaitez pas utiliser avec Cloud Volumes ONTAP.
+
** https://docs.netapp.com/us-en/data-services-data-classification/concept-classification.html["En savoir plus sur la classification NetApp"^]
** https://docs.netapp.com/us-en/data-services-backup-recovery/concept-backup-to-cloud.html["En savoir plus sur NetApp Backup and Recovery"^]
** link:concept-worm.html["En savoir plus sur le stockage WORM sur Cloud Volumes ONTAP"]
+

TIP: Si vous souhaitez utiliser WORM et la hiérarchisation des données, vous devez désactiver la sauvegarde et la récupération et déployer un système Cloud Volumes ONTAP avec la version 9.8 ou supérieure.



. * Compte du site de support NetApp * : si vous avez plusieurs comptes, sélectionnez celui que vous souhaitez utiliser.
. Vérifiez ou modifiez les détails que vous avez saisis, puis cliquez sur *Créer*.


.Après avoir terminé
La console déploie le système Cloud Volumes ONTAP .  Vous pouvez suivre la progression sur la page Audit.

En cas de problème lors du déploiement du système Cloud Volumes ONTAP, veuillez consulter le message d'erreur. Vous pouvez également sélectionner *Recréer l'environnement* sur le système pour poursuivre le déploiement à l'aide du mode assistant  `Advanced`.


CAUTION: Une fois le processus de déploiement terminé, ne modifiez pas les configurations Cloud Volumes ONTAP générées par le système dans le portail cloud AWS ou Azure, en particulier les balises système. Toute modification apportée à ces configurations peut entraîner un comportement inattendu ou une perte de données.
